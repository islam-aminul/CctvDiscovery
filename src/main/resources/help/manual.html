1. What it does

The tool surveys a network for IP cameras and recorders (NVRs and DVRs). For each one it finds, it records the make, model and firmware, finds its video streams, measures them (resolution, codec, bitrate, frame rate), and lists anything that needs attention, such as video that anyone on the network can watch without a password. Results can be saved as an Excel workbook, a CSV file or a JSON file.

Devices are found in two ways at once: cameras that announce themselves over ONVIF, and every address in the chosen range checked for the ports cameras use. Each device is then identified over ONVIF, or by trying the stream addresses its maker uses.

Only survey networks you are responsible for. The tool signs in to devices with the usernames and passwords you give it, and a wrong password counts as a failed sign-in on the device.

2. Installing and starting

2.1 The single-file package

Run CctvDiscovery-<version>-sfx.exe. It unpacks itself to %LOCALAPPDATA%\Programs\CctvDiscovery\<version> and starts the tool. Nothing else needs installing: it carries its own Java runtime. Run it again whenever you want to start the tool, or start CctvDiscovery.exe from that folder.

Windows may say the publisher is unknown. The package is signed, but with a certificate Windows does not trust by default. Choose More info, then Run anyway.

2.2 The zip

Unzip CctvDiscovery-<version>.zip anywhere and run CctvDiscovery.exe.

2.3 Where it keeps things

Settings, remembered stream paths and logs are kept in %LOCALAPPDATA%\CctvDiscovery, whichever copy of the program is running. Usernames and passwords are never saved; they last for the session.

4. A survey, step by step

4.1 Where to look

Choose Choose network.... The Simple tab takes one of:

  • An adapter on this computer: its whole subnet. Real adapters are listed before virtual ones (Hyper-V, WSL, VMware, VPNs), so the first is usually the right one.
  • An address range, such as 192.168.1.10 to 192.168.1.60.
  • A CIDR block, such as 192.168.1.0/24.
  • A list of addresses, ranges and blocks, separated by commas or new lines.

Choosing an adapter

The Advanced tab combines several adapters, ranges and blocks in one scan. Overlapping entries are scanned once.

Several networks in one scan

Cameras that announce themselves from outside the chosen range are left out, and the progress line says how many were.

4.2 Sign-in details (optional)

Add the usernames and passwords used on site, up to 8. Each is tried in turn on every device until one works. Devices that need no password are found and measured without any; that is also how a camera open to anyone is detected.

Passwords are masked in the list; right-click an entry to edit or delete it

Every wrong password is a failed sign-in on each device it is tried on, and some makes lock the account after a few. Put the most likely password first.

4.3 How thoroughly to check

The three levels of checking

  • Quick Check asks for the stream description only. Fast, but a camera can answer and still send no picture.
  • Stream Test confirms video data is arriving.
  • Video Capture decodes a picture. The slowest and the most reliable; use it for audits.

4.4 Run the scan

Choose Start scan. Devices appear as they are found, and each row's status changes as it is identified and measured. Stop keeps everything found so far.

A scan in progress

4.5 Review

A finished scan with a camera selected: its streams, then its issues

Right-click a device for:

  • Try other credentials... to sign in to that device again with a different username and password, without scanning everything again.
  • Copy stream addresses, ready to paste into a player such as VLC.

4.6 Report

Choose Export report... and enter the location code: the code of the test centre, premises, site or LAN you surveyed. It goes into the report and the file name.

The only question before saving

Then pick where to save it and the file type: Excel workbook (the default), CSV, or JSON. Open a saved scan... reads a JSON file back into the window.

5. Reading the results

5.1 Row colours

Green: finished, with video.

Amber: being identified or measured.

Red: needs a password, or none of those entered was accepted.

Grey: not a camera or recorder, such as a router.

Blue: found, not yet checked.

5.2 Status

StatusMeaning
CompletedIdentified, with at least one stream measured.
Sign-in neededThe device asks for a password and none of those entered worked, or none was entered. Add the right one and use Try other credentials...
No videoA camera or recorder, but no stream address it serves was found. If its stream path is unusual, add it under Settings, Stream Paths.
Not a cameraSomething on the network that is not a camera or recorder.
ErrorSomething went wrong while checking it; the note says what.

5.3 Issues

Each device lists what needs attention, from High to Info. For example:

  • High: video readable without a password.
  • Medium: device details readable over ONVIF without a password; the device clock out of step with this computer; a stream that browsers cannot play without converting it.
  • Info: ONVIF refused the password, or needs one, so the model and firmware could not be read even though video was found; a device reachable only over its maker's own protocol.

6. Settings

Saved for this Windows user, in the folder shown at the bottom of the dialog. Reset to Defaults asks before it changes anything.

6.1 Ports

The ports checked on every address

Only change these for cameras on non-standard ports. A port is recognised by what answers on it, not by its number, so adding it here is enough.

6.2 Stream Paths

Extra main and sub stream paths

The tool knows the stream paths of the common makes. Add a main and sub path pair here for a model it does not know. Paths that work are remembered per make for later scans.

7. The report

The Excel workbook has five sheets:

  • Summary: the location code, when and by whom, and the totals.
  • Devices: one row per device: address, MAC, make, model, firmware, serial number, open ports and status.
  • Streams: one row per stream, with its measurements and address.
  • Findings: every issue, with its severity and what to do about it.
  • Host: the computer the survey was run from.
Stream addresses include the username and password that worked, so they can be opened straight away. Treat the file as you would the passwords themselves. The workbook is locked against editing (values can be selected, copied and filtered, but not changed), but it is not encrypted: anyone with the file can read it.

8. Troubleshooting

No devices found

  • Check the range in step 1 is the network the cameras are on.
  • If Windows Firewall asks whether to allow the tool, allow it; otherwise cameras' announcements cannot reach it.
  • Cameras on another subnet are found by address only. Announcements and MAC addresses from the computer's own table only work on this computer's subnet; ONVIF can still report a MAC.

Devices show Sign-in needed

  • Add the site's credentials and use Try other credentials... on the device.
  • Some makes keep ONVIF users separate from the web login; add the ONVIF account too.
  • If a device has locked its account after failed sign-ins, wait for it to unlock before trying again.

A scan takes long

  • Large ranges take longer; a /24 usually takes a minute or two.
  • Video Capture takes about 10 seconds per stream; Quick Check is faster.

The tool does not start

  • Run the package again; it replaces the unpacked copy.
  • Logs are in %LOCALAPPDATA%\CctvDiscovery\logs.

9. Questions

Does it change anything on the cameras?

No. It reads device information and video, and changes no settings.

Which makes does it support?

Any camera or recorder that speaks ONVIF or RTSP. Stream paths are built in for Hikvision (with Prama, HiLook, HiWatch and EZVIZ), Dahua (with Imou), CP Plus, Uniview, Axis, Bosch, Hanwha, Panasonic, Sony, Vivotek, Amcrest and Foscam.

Can I open the streams from the report?

Yes. Paste a stream address into a player such as VLC.

What does the clock difference mean?

How far the device's clock is from this computer's. A large difference makes recordings hard to match to real events; point the device at a time server.
